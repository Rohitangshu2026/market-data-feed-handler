A feed handler rebuilds an exchange's order book from a stream of events that a lossy
link damages, and checks the result against the exchange's own book. Answer each
question, or press Enter for the value in [brackets]; q quits.

Scenarios:
  1  watch     a live stream with heavy loss
  2  burst     a run of lost events, recovered by one retransmission
  3  reorder   late and doubled events, absorbed with no recovery
  4  tail      the last events lost; the heartbeat finds them
  5  outage    a gap older than the exchange's history: a snapshot
  6  random    any damage you like, at any scale, timed
  7  lamport   two handlers with skewed clocks hand the stream over
  8  all       every scenario but watch, one after another, with their defaults
  Which scenario? A number or a name [random] random
  How many events should the exchange publish? [1,000,000] 50000
  Seed? Any number replays a run exactly; Enter picks a random one [random] 658947
  Chance an event is lost, e.g. 20% or 0.2? [20%] 30%
  Chance an event arrives twice? [1%]
  Chance an event arrives one place late? [2%]
  Change the handler's settings too (reorder window, recovery, book size)? [no]
  How many events to show at each end of the stream, and what happened to each? [5] 4
